# Архитектура TutorHub

Документ описывает, как устроен проект внутри. Написан по актуальному коду репозитория.

## Общая схема

TutorHub — классическое Django-приложение: браузер отправляет запрос, Django находит нужную функцию-представление (view), та берёт данные из базы через модели и отдаёт HTML-шаблон.

```
Браузер → config/urls.py → <app>/urls.py → <app>/views.py → models → SQLite
                                                   ↓
                                          templates/*.html → HTML-ответ
```

## Приложения

| Приложение | За что отвечает | Модели |
|---|---|---|
| `config` | настройки проекта, корневой роутинг | — |
| `pages` | главная, «О нас», «Контакты» | — |
| `tutors` | каталог репетиторов и страница репетитора | `Tutor` |
| `subjects` | список предметов | `Subject` |
| `requests` | форма заявки на занятие, отзывы | `Request`, `Review` |

## Модели данных

### Subject (предмет) — `subjects/models.py`

| Поле | Тип | Описание |
|---|---|---|
| `name` | CharField(100) | название предмета |
| `slug` | SlugField, уникальное | часть адреса, например `matematika`; используется в фильтре `?subject=` |

### Tutor (репетитор) — `tutors/models.py`

| Поле | Тип | Описание |
|---|---|---|
| `name` | CharField(100) | имя |
| `photo` | ImageField, `upload_to='tutors/'` | фото, хранится в `media/tutors/` |
| `description` | TextField | описание |
| `subject` | ForeignKey → Subject | предмет (`related_name='tutors'`) |
| `experience` | IntegerField | опыт в годах |
| `price` | IntegerField | цена за час, ₽ |
| `is_active` | BooleanField, по умолчанию `True` | показывать ли репетитора на сайте |

### Request (заявка) — `requests/models.py`

| Поле | Тип | Описание |
|---|---|---|
| `name` | CharField(100) | имя заявителя |
| `phone` | CharField(20) | телефон |
| `email` | EmailField | email |
| `subject` | ForeignKey → Subject | выбранный предмет |
| `tutor` | ForeignKey → Tutor, необязательное (`SET_NULL`) | выбранный репетитор |
| `date` | DateField | желаемая дата занятия |
| `created_at` | DateTimeField, `auto_now_add` | когда создана заявка |
| `is_processed` | BooleanField, по умолчанию `False` | обработана ли менеджером |

### Review (отзыв) — `requests/models.py`

| Поле | Тип | Описание |
|---|---|---|
| `tutor` | ForeignKey → Tutor (`related_name='reviews'`) | о ком отзыв |
| `author` | CharField(100) | автор |
| `text` | TextField | текст отзыва |
| `rating` | IntegerField, по умолчанию 5 | оценка |
| `created_at` | DateTimeField, `auto_now_add` | дата создания |

### Связи

```
Subject 1 ──< Tutor 1 ──< Review
   │            │
   └──< Request >┘   (Request.tutor может быть пустым)
```

- Один предмет — много репетиторов.
- Один репетитор — много отзывов.
- Заявка всегда связана с предметом и, по желанию, с конкретным репетитором.
- При удалении предмета удаляются его репетиторы и их отзывы (`CASCADE`). При удалении репетитора заявка остаётся, поле `tutor` становится пустым (`SET_NULL`).

## Как проходит запрос

Пример: пользователь открывает `/tutors/?subject=fizika&page=2`.

1. `config/urls.py` видит префикс `tutors/` и передаёт запрос в `tutors/urls.py`.
2. `tutors/urls.py` сопоставляет пустой путь функции `tutor_list`.
3. `tutor_list` (в `tutors/views.py`):
   - берёт активных репетиторов `Tutor.objects.filter(is_active=True)`;
   - если в адресе есть `subject`, оставляет только репетиторов с таким `subject__slug`;
   - режет список на страницы по 6 штук (`Paginator`), номер страницы берёт из `?page=`;
   - передаёт в шаблон страницу репетиторов, список всех предметов и выбранный предмет.
4. Шаблон `templates/tutors/list.html` рисует кнопки-фильтры по предметам, карточки и переключатель страниц. Выбранный предмет сохраняется в ссылках пагинации.

Отправка заявки: форма `templates/requests/form.html` отправляет POST на `/request/`. Функция `request_create` создаёт объект `Request` из полей формы и перенаправляет на `/request/success/`.

## Шаблоны и статика

- `templates/base.html` — общий каркас (шапка с меню, подвал). Остальные шаблоны наследуются от него через `{% extends 'base.html' %}`.
- Страницы: `index.html`, `about.html`, `contacts.html`, `tutors/list.html`, `tutors/detail.html`, `subjects/list.html`, `requests/form.html`, `requests/success.html`.
- Стили: `static/css/style.css`.
- Статику в продакшене раздаёт WhiteNoise (`CompressedManifestStaticFilesStorage`), собирается командой `collectstatic` в папку `staticfiles/`.
- Медиафайлы (фото) лежат в `media/` и в режиме `DEBUG=1` раздаются самим Django (см. конец `config/urls.py`).

## Админ-панель

Зарегистрированы все четыре модели. Настроено:

- `Tutor`: колонки имя / предмет / опыт / цена / активность, фильтры по предмету и активности.
- `Subject`: slug заполняется автоматически из названия.
- `Request`: колонки имя / предмет / репетитор / дата / обработана, фильтры по предмету и статусу.
- `Review`: колонки автор / репетитор / оценка / дата, фильтр по оценке.

## Настройки (config/settings.py)

- База данных: SQLite, файл `db.sqlite3` в корне проекта.
- Язык `ru-ru`, часовой пояс `Europe/Moscow`.
- `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS` читаются из переменных окружения.
- Подключён `whitenoise.middleware.WhiteNoiseMiddleware` для статики.

## Известные ограничения (на момент написания)

Эти пункты стоит учесть при развитии проекта и обсудить с командой:

1. **Нет Pillow в `requirements.txt`.** Поле `ImageField` требует библиотеку Pillow. Локально она установлена в `venv`, но в списке зависимостей её нет, поэтому сборка в Docker может упасть на `migrate`.
2. **Отзывы не выводятся на сайте.** Модель `Review` есть, но шаблон `tutors/detail.html` отзывы пока не показывает (связь `tutor.reviews` доступна).
3. **Нет валидации оценки.** Поле `rating` принимает любое целое число, ограничения 1–5 нет.
4. **Форма заявки без проверки на сервере.** `request_create` берёт значения из `request.POST` напрямую, без Django-формы: пустая или неверная дата вызовет ошибку, а не сообщение пользователю.
5. **Название приложения `requests`** совпадает с названием популярной Python-библиотеки `requests`. Сейчас конфликта нет, но при установке этой библиотеки он возможен.
6. **Фильтры в разработке.** Сейчас в каталоге работает только фильтр по предмету и пагинация по 6 штук. Цена, опыт, поиск, сортировка и пагинация по 9 запланированы на спринт 2.
7. **Тесты** — пока только пустые заготовки.
