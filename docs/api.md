# Адреса сайта (API)

TutorHub не имеет отдельного JSON API: сайт отдаёт HTML-страницы. Этот документ описывает адреса, методы и параметры. Источник: `config/urls.py` и `urls.py` каждого приложения.

## Таблица адресов

| URL | Метод | Имя маршрута | Что возвращает |
|---|---|---|---|
| `/` | GET | `pages:index` | Главная: до 6 активных репетиторов |
| `/about/` | GET | `pages:about` | Страница «О нас» |
| `/contacts/` | GET | `pages:contacts` | Страница «Контакты» |
| `/tutors/` | GET | `tutors:list` | Каталог репетиторов (с фильтром и пагинацией) |
| `/tutors/<id>/` | GET | `tutors:detail` | Страница репетитора, `404` если такого `id` нет |
| `/subjects/` | GET | `subjects:list` | Список предметов |
| `/request/` | GET | `requests:create` | Форма заявки |
| `/request/` | POST | `requests:create` | Создание заявки, затем редирект на `/request/success/` |
| `/request/success/` | GET | `requests:success` | Страница «Заявка отправлена» |
| `/admin/` | GET | — | Админ-панель Django (нужен вход) |
| `/media/...` | GET | — | Фото репетиторов (только при `DEBUG=1`) |

## Каталог: `/tutors/`

### Параметры строки запроса (GET)

| Параметр | Пример | Описание | Статус |
|---|---|---|---|
| `subject` | `?subject=matematika` | slug предмета; без параметра показываются все | работает |
| `page` | `?page=2` | номер страницы (по 6 репетиторов); неверный номер заменяется на ближайший допустимый | работает |

Параметры можно комбинировать: `/tutors/?subject=fizika&page=2`. В ссылках пагинации выбранный предмет сохраняется.

Показываются только репетиторы с `is_active = True`.

### Запланировано на спринт 2 (в коде ещё нет)

Названия параметров согласованы с Вадимом. Сейчас работают только `subject` и `page`, остальные в разработке.

| Параметр | Назначение |
|---|---|
| `price_min`, `price_max` | цена за час от и до |
| `experience_min` | минимальный опыт, лет |
| `q` | поиск по тексту |
| `sort` | `price_asc`, `price_desc`, `experience_desc`, `rating_desc` |
| `page` | номер страницы (планируется по 9 вместо текущих 6, с сохранением фильтров) |

Пример от Вадима: `/tutors/?subject=2&price_min=1000&price_max=3000&sort=price_asc&page=1`

> Расхождение: в примере `subject=2` (номер предмета), а текущий код фильтрует по slug (`?subject=matematika`). Уточнить у Вадима, какой вариант будет итоговым. Сортировка `rating_desc` предполагает средний рейтинг из отзывов; отдельного поля рейтинга у репетитора в модели нет.

## Предметы, доступные для фильтра

Значение `subject` берётся из поля `slug` предмета. В тестовых данных:

| Предмет | slug |
|---|---|
| Математика | `matematika` |
| Английский язык | `english` |
| Физика | `fizika` |
| Русский язык | `russkiy-yazyk` |
| Информатика | `informatika` |
| Химия | `khimiya` |

## Форма заявки: POST `/request/`

Формат: `application/x-www-form-urlencoded` (обычная HTML-форма). Обязателен CSRF-токен (`{% csrf_token %}` в шаблоне).

| Поле | Обязательное | Описание |
|---|---|---|
| `name` | да | имя, до 100 символов |
| `phone` | да | телефон, до 20 символов |
| `email` | да | адрес электронной почты |
| `subject` | да | `id` предмета |
| `tutor` | нет | `id` репетитора; пустое значение сохраняется как «без репетитора» |
| `date` | да | желаемая дата занятия, формат `ГГГГ-ММ-ДД` |

Ответы:

- Успех: `302` редирект на `/request/success/`; в базе создаётся заявка со статусом «не обработана».
- Ошибка CSRF: `403`.
- Некорректные данные (например, пустая дата): сейчас серверной проверки нет, возможна ошибка `500`. См. ограничения в [architecture.md](architecture.md).

Пример:

```http
POST /request/
Content-Type: application/x-www-form-urlencoded

name=Иван&phone=%2B79991234567&email=ivan%40example.com&subject=1&tutor=3&date=2026-11-10&csrfmiddlewaretoken=...
```

## Отзывы

Публичного адреса для отзывов нет. Отзывы (модель `Review`) создаются и редактируются в админ-панели: `/admin/` → «Отзывы». Через сайт они пока не выводятся.
